# DEBUG RX 空闲电平与总线请求回流修复

## 问题与原因

0x0208 在主控仅通过真实 DXL 总线读取时，偶尔返回额外的 SYNC_READ 请求副本或残片。
50 Hz、600 秒测试出现 3 次解析错误和 1 次超时；200 Hz 下能够连续复现。
诊断状态出现 DEBUG RX 丢弃/溢出及回显不匹配，`last_error=5`。

当时 PA10 配置为 `GPIO_Mode_IN_FLOATING`，GPIO 输入寄存器读为低。
本次测试程序没有向 DEBUG 端发送应用数据，USART1 的 DMA 接收缓冲却含有与主总线
请求和舵机回复相吻合的损坏字节。透明桥将这类伪接收再次注入真实总线，造成回流。

问题是 DEBUG RX 没有可靠的 UART 空闲高电平，受到总线相关串扰。
具体线缆/PCB 上的耦合路径没有用示波器测定；以下单变量对照确认了输入偏置的因果作用。

旧版文本 CLI 不会把任意接收字节转发到电机总线。0x0208 增加透明转发后，
原有浮空输入就可能将串扰扩大为主总线故障。

## 单变量实物对照

保持接线、主控、波特率及桥接功能不变，只修改 PA10 的输入模式：

| 条件 | 实物结果 |
|---|---|
| 原版 0x0208 | IMU 200 Hz，255 次成功、5 次失败后停止 |
| 仅改 PA10 为 `GPIO_Mode_IPU` | IMU 200 Hz，1,000/1,000 成功；状态始终为 3，错误码 0 |
| 同一上拉构建的完整负载扫描 | 单独 IMU 200 Hz、混合 IMU 200 Hz/舵机 50 Hz、整组 50 Hz 均无通信错误 |
| 重新烧回原版并完整复位 | IMU 200 Hz 前 5 次全部失败，再次出现请求残片 |

上拉构建在负载扫描后，PA10 输入读为高，512 字节 DEBUG RX DMA 缓冲保持全零。
原版 GPIOA CFGHR 为 `0x388444b4`，上拉版为 `0x388448b4`；仅 PA10 配置字段变化。
输入寄存器从 `0x220` 变为 `0x620`，PA10 对应位由 0 变为 1。
换回原版后错误立即复现，排除了仅靠重启消除旧状态的解释。

## 修复范围

- PA10 使用内部上拉，未驱动的 DEBUG RX 保持 UART 空闲高电平。
- 诊断版本更新为 `0x0209`，与已发布的 0x0208 区分。
- 透明桥、原始字节转发、已有溢出检测、回显处理及维护解锁均保留。
- IMU 名义 240 Hz、主控 50 Hz、ID 200、1 Mbps、坐标和比例换算均不变。

本次测试仅使用读取指令，舵机配置保持原值。修复通过固件完成，电机总线接线保持原状。

## 最终 0x0209 验证

- 固件 14,328 字节，烧录后完整读回一致；末尾 8 KiB 配置区与修复前一致。
- Debug 与 UBSan 宿主测试分别 6/6 通过，软总线工具自检通过。
- 真实 Rust 主控读取路径、16 设备、50 Hz 持续 600 秒：30,001/30,001 成功，
  零错误、零跳周期，平均 7.172 ms，P99 7.599 ms，最大 7.811 ms。
- IMU 就绪后无就绪丢失，最长连续重复块为 1 次。
- 单 IMU 200 Hz 持续 60 秒：12,000/12,000 成功，平均 2.617 ms，P99 2.781 ms，
  零跳周期，线上字节占用 7.605%。
- IMU 平均 200 Hz / 舵机 50 Hz 持续 60 秒：12,000/12,000 成功，平均 3.663 ms，
  P99 6.876 ms，零跳周期，线上字节占用 25.606%。混合读取不保证每 5 ms 均匀到达。
- 整组目标 200 Hz 读取无通信错误，但实际只有 148.064 Hz，仍受约 6.7 ms 的整组
  事务耗时限制；这项容量探测不代表整组 200 Hz 达标。
- 额外 1,000/1,000 个 IMU 样本和四元数有效性检查通过；融合更新约 251.29 Hz，
  数据年龄 0–3 ms。诊断状态保持 3、错误码保持 0，桥接告警未复现。
