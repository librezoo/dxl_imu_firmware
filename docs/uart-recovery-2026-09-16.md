# 合并读取失败的定位与修复

本次针对复刻 IMU 板的 Dynamixel 通信失败。参考官方 robotd 的请求：
1 Mbps，地址 124，长度 12，SYNC_READ 顺序为
`200,20,21,22,23,24,30,31,32,33,34,10,11,12,13,14`。
采集器只发送 READ/SYNC_READ，未启动 robotd/padd，未写舵机寄存器。

## 实机证据与推断边界

- 单独读 IMU 的第一轮 10 秒采样为 500/500 成功；加入 15 个舵机后出现连续失败。
- 后续两轮原始字节采集分别为 21/46、122/148 次完整成功。异常事务中能看到
  多份相同的 ID 200 状态包；单次事务最多出现 31、44 个 ID 200 包头，
  混有截断帧及与舵机回复交叠的字节。
- 成功读取的固件诊断版本为 `0x0200`。采样计数从 148150 降至 7494，
  复位原因位 0 为 1（看门狗复位）；期间采集器没有发送复位指令。
- 这些证据与下述 DMA 循环重放缺陷一致。但未烧录修复版前，不能声称已经完成
  实机因果确认，或排除了 UART、电气时序等其他问题。

## 三处修复

### DMA 环形缓冲区末端

旧代码计算 `head = 512 - DMA1_Channel3->CNTR`。循环 DMA 计数到零、尚未
重装载的边界上，head 为 512；tail 每次都 `% 512`，永远无法等于它。
收包循环因而可能重复处理旧请求、连续发送相同回复，并阻止主循环喂狗。

现在将 head 也归一化到环形缓冲区范围。回归测试模拟 tail=500、剩余计数为 0：
旧算法在一整圈后仍未退出；修复后只消费末尾 12 字节。也覆盖重装载计数 512
及跨界后继续接收的情况。

### Dynamixel 2.0 字节填充

旧解析器先去填充再检查 Length/CRC，旧发送器先算 CRC 再填充，两者自测能互相
配合，但与标准线协议不兼容。数据含 `FF FF FD` 时会出错。

修复为接收时先检查线上的 Length/CRC，再仅对指令和参数去填充；发送时先填充
指令/参数、更新 Length，再计算 CRC。Header、Length、CRC 本身不参与填充。

独立测试向量：ID 20、状态 0、载荷 `FF FF FD 00`，正确线包为：

```text
FF FF FD 00 14 09 00 55 00 FF FF FD FD 00 CE 7D
```

旧代码拒收该包；旧发送结果的 Length 和 CRC 也不符合线协议。
测试另含 ROBOTIS 手册的 PING/状态包向量，避免只做同一实现的编码解码往返。

### 坏帧后的接收恢复

旧硬件收包器只有解析成功才清空累计数据；失败时把后续包继续拼上，直到 512
字节或超过 30 ms 的接收间隙。50 Hz 请求可能一直没有这样的空闲期。

现在用可独立测试的流式收包器消费完整坏帧，并在新包头处恢复。保留重叠包头
前缀，不把有效 CRC 中偶然出现的包头字节误判为新包。状态回复一律不再触发
设备回复，防止本机回显被当作指令。

测试覆盖所有请求截断位置、错误长度、坏 CRC、额外 FF、合法填充、CRC 恰好
构成包头的边界、其他舵机状态包、自己的状态回显及官方合并请求。

## 验证与后续烧录

修复版诊断版本为 `0x0201`，地址仍为 160，寄存器布局不变。
普通 Debug 与 UBSan（同时开启 `-Wall -Wextra -Werror`）测试均为 4/4 通过。
本机 Apple ASan 在进入 main 前的运行库初始化中发生自旋，已终止，不能将其
记录为通过；采样堆栈显示问题位于 ASan/Dyld 初始化。

使用官方 MounRiver macOS 工具包 2.4.0 中的 RISC-V Embedded GCC 8.2.0，
通过仓库现有 CMake MCU 入口完成编译、链接及 HEX/BIN 生成。SDK 仍仅使用
仓库内的 54 个文件，已按现有清单检查没有变化。产物位于 `build-ch32/`：

- `imu_power_ch32.bin`：11,392 字节。
- `imu_power_ch32.hex`：同一固件的 Intel HEX。
- `imu_power_ch32`、`imu_power_ch32.map`：ELF 与链接布局。

`size` 输出 text=11,344、data=48、bss=4,264 字节；Flash 链接范围仍为
56 KiB，末尾两个配置页保留。此次未改动 MCU 源码列表、SDK、链接脚本或
`build.ps1`；Windows 构建入口继续使用同一组源码。

当前 WCH-Link 未连接，因此尚未烧录及实机复测。接上后需先确认目标芯片、
保存当前镜像与配置，再烧录构建出的镜像，确认诊断版本 `0x0201`，重复同样的
只读合并采样并检查重复回复、坏帧、采样计数及看门狗复位。

本轮没有修改 IMU 量程、零偏、安装方向、姿态映射、舵机配置或电池保护。
此前按官方系数换算出的 Z 轴约 -5.8 deg/s 仍是独立待核查项；需先确认静止状态
及实际量程，不能用通信修复代替测量准确性验证。

协议依据：[ROBOTIS Dynamixel Protocol 2.0](https://emanual.robotis.com/docs/en/dxl/protocol2/#packet-process)。
